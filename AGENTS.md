# AGENTS.md — память директора проекта DMTools

Это файл-память для ИИ-агентов проекта. Цель — чтобы каждый агент (и сам
директор) начинал сессию уже «в курсе» и с каждым разом работал лучше.
Обновляй его при обнаружении несоответствий или новых норм.

## Кодовая карта (устарело? — обнови)

| Файл | Назначение |
|------|-----------|
| `main.py` | Точка входа GUI-приложения |
| `gui.py` | Tkinter-интерфейс: вкладки, меню, обработка событий (~6170 строк, стараться НЕ раздувать) |
| `converter.py` | Чтение PDF→CSV, генерация этикеток, GS1/GTIN-валидация, XLSX |
| `converter_utils.py` | **Чистая логика конвертации файлов** (30 пар), хелперы кириллицы в PDF, `CONV_SUPPORTED` |
| `scanner.py` | Приём объединённого сканера (клавиатура / COM) |
| `scanner_devices.py` | Обнаружение COM-портов и HID-устройств |
| `scanner_diag.py` | Диагностика сканера |
| `updater.py` / `updater_helper.py` | Самообновление через `update.json` на GitHub |
| `version.py` / `version_info.txt` | Единый источник версии `APP_VERSION` |
| `build_exe.ps1` | Сборка EXE (PyInstaller) |
| `.github/workflows/ci.yml` | CI: автотесты на push, автосборка при теге |
| `tests/` | Юнит-тесты (unittest): `test_gui.py`, `test_converter_utils.py`, `test_converter.py` (ядро «Честного знака») |

## Локальные нормы (что принято в этом репозитории)

- Запуск: `python main.py`. Тесты: `python -m unittest discover -s tests -v`.
- Сборка EXE: `pwsh -ExecutionPolicy Bypass -File .\build_exe.ps1`.
- Изменяя логику, ДОБАВЬ/ОБНОВИ юнит-тесты — тесты должны оставаться зелёными.
- НЕ подделывай тесты под код: если тест ломается, почини код или обнови тест по смыслу.
- Чистая логика — в модулях (converter_utils), а не в `gui.py`; UI-обёртки — в `gui.py`.
- Не коммить runtime-артефакты: `dist/`, `build/`, `*.log`, `.venv-build/`.
- Версия поднимается и согласуется во всех местах перед релизом.
- Кодировка исходников — UTF-8; комментарии на русском, где пишешь для себя/команды.

## Самокоррекция

1. Если кодовая карта выше устарела — обнови её: добавь/поправь строки таблицы.
2. Если пользователь дал норму о том, как вести работу в этом проекте — запиши её
   в «Локальные нормы», чтобы будущие сессии её наследовали.
3. Если обнаружил повторяющуюся задачу — оформи её как скилл (skill-creator),
   чтобы агенты переставали каждый раз «переизобретать» решение.

## Система ежедневного обучения (директор обязан каждый раз)

1. В конце работы — сохрани в долговременную память (memory tool) 1-2 факта:
   что нового в DMTools, какие решения приняты, какие ошибки находены.
2. Проверь, не пора ли создать/обновить скилл под повторяющийся процесс.
3. Делегируй профильные задачи агентам из `agent/dmtools-*.md` через Task-tool
   с чётким заданием, вместо того чтобы делать всё самому.
4. Подведи итог сессии кратко и предложи план дальше.

## Команда агентов (штат директора)

- `dmtools-architect` — архитектура, выделение модулей, чистота кода.
- `dmtools-tester` — юнит-тесты, регрессии, покрытие.
- `dmtools-reviewer` — ревью перед коммитом/релизом, поиск багов/утечек.
- `dmtools-researcher` — изучение лучших практик агентов и технологий.
- `dmtools-docs` — README/CHANGELOG/лицензии.
- `dmtools-release` — сборка EXE, релизы, обновление через приложение.
