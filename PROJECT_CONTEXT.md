# PDFDataMatrixToCSV — контекст проекта для ИИ-агента

## Назначение

Проект конвертирует PDF-файлы с кодами GS1 DataMatrix «Честный знак» в CSV.
Основной сценарий: пользователь выбирает один PDF или папку с PDF, программа рекурсивно находит файлы, декодирует DataMatrix на каждой странице и сохраняет по одному CSV для каждого PDF. По отдельному флажку результаты можно объединить в один CSV.

После переноса рабочая папка проекта:

```text
D:\dev\pyhton\PDFDataMatrixToCSV
```

## Что важно не перепутать

- Это отдельный автономный проект. Старые скрипты в `tools\` из соседнего проекта не являются частью этой версии.
- GUI не вызывает отдельный `.py`-скрипт через subprocess. Вся логика находится внутри проекта и импортируется напрямую.
- На выходе CSV содержит одну колонку `code`.
- По умолчанию коды записываются буквально, без CSV-экранирования. Управляющие символы GS / ASCII 29 сохраняются как реальные байты.
- Если включен флажок «Добавить экранирование», используется стандартное CSV-экранирование Python `csv.QUOTE_MINIMAL`.
- По умолчанию CSV сохраняется в ту же папку, где лежит исходный PDF.
- Если включен флажок «Объединять в один CSV файл», становится доступно поле пути к общему CSV.
- При включении флажка пустое поле общего CSV автоматически заполняется на основе выбранного источника. Если путь всё равно не указан, обработка не запускается.
- Для выбранной папки общий файл по умолчанию создаётся внутри неё и получает имя `<название папки>.csv`.
- Для выбранного PDF общий файл по умолчанию создаётся рядом с ним и получает имя `<название PDF>.csv`.
- Перед перезаписью существующего общего CSV программа запрашивает подтверждение. При отказе обработка не запускается.
- В обычном режиме уже существующие отдельные CSV перезаписываются.
- Если несколько выходных файлов получают одинаковый полный путь, к имени добавляются суффиксы `_2`, `_3` и далее.

## Как работает декодирование

1. `converter.py` открывает PDF через PyMuPDF:

   ```python
   document = pymupdf.open(pdf_path)
   ```

2. Каждая страница рендерится в grayscale-изображение:

   ```python
   page.get_pixmap(
       matrix=pymupdf.Matrix(scale, scale),
       colorspace=pymupdf.csGRAY,
       alpha=False,
   )
   ```

3. По странице целиком запускается `zxingcpp.read_barcodes(image)`.
4. GS1 DataMatrix определяется по AIM Symbology Identifier `]d2`.
5. Для каждой страницы ожидается ровно один GS1 DataMatrix. Ноль или больше одного считаются ошибкой страницы.
6. DPI перебираются по умолчанию так: `216`, затем `288`, затем `360`, затем `400`.

Причина выбора `216 DPI` как первой попытки: тестовые PDF хранят DataMatrix как векторную форму, поэтому повышение DPI даёт декодеру больше реальных пикселей на модуль кода, а не простой апскейл растра. Более высокие DPI используются как fallback.

## Проверки кода

Текущая проверка ориентирована на структуру GS1 и типичный полный код маркировки:

- код должен быть GS1 DataMatrix с FNC1, то есть `symbology_identifier == "]d2"`;
- структура должна соответствовать:

  ```text
  01 + GTIN(14) + 21 + serial + GS + 91 + crypto_key + GS + 92 + crypto_code
  ```

- GTIN должен состоять из 14 цифр;
- контрольная цифра GTIN проверяется;
- должны присутствовать ровно два разделителя GS / ASCII 29;
- AI `01`, `21`, `91`, `92` должны находиться в ожидаемых местах;
- поля `21`, `91`, `92` проверяются на допустимые GS1-символы;
- поля проверяются по диапазонам GS1:
  - `21`: от 1 до 20 символов;
  - `91`: от 1 до 90 символов;
  - `92`: от 1 до 90 символов.

Важно: строгие длины «Честного знака» `21=13`, `91=4`, `92=44` сейчас не зашиты как обязательное условие. Если нужна строгая проверка именно под эти товарные группы, ее надо добавлять отдельно.

## Что программа не проверяет

- криптографическую подлинность AI `92`;
- статус кода в системе «Честный знак»;
- принадлежность GTIN конкретному товару в каталоге;
- качество печати по ISO/IEC 15415;
- физический размер DataMatrix или этикетки;
- соответствие макета требованиям конкретного термопринтера.

```powershell
cd D:\dev\pyhton\PDFDataMatrixToCSV
powershell -ExecutionPolicy Bypass -File .\build_exe.ps1
```

Результат:

```text
dist\PDFDataMatrixToCSV.exe
```

На машине пользователя для запуска EXE Python и библиотеки не требуются.

## Runtime-зависимости

- PyMuPDF — рендеринг страниц PDF в изображения.
- Pillow — работа с изображениями.
- zxing-cpp — распознавание DataMatrix.
- tkinter — GUI, обычно входит в стандартную поставку Python на Windows.

## Юридический момент

Перед распространением EXE надо учитывать лицензии зависимостей. Особенно PyMuPDF: у него AGPL или коммерческая лицензия Artifex.

## Исторический контекст

Проект был создан как замена набору отдельных скриптов:

- сначала был CLI-скрипт PDF → CSV;
- затем был GUI-скрипт-обертка;
- затем логика была перенесена в отдельный проект `PDFDataMatrixToCSV`, чтобы собрать единый автономный EXE без зависимости от внешнего Python и без вызова отдельного `.py` через subprocess.

Проверялось на PDF с кодами «Киндеры июль 03.07.26». Для известных тестовых файлов извлечение давало коды длиной 85 байт с двумя GS-разделителями.
